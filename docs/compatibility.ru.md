# Контракт совместимости

[English](compatibility.md) · [Русский](compatibility.ru.md)

## Эталон и область действия

Эталон — Context Mapper DSL 6.12. Исходная версия репозитория для подготовительных
работ — коммит 351c92b1f81081a98381ab76faec7412d987c37e. Существующие корпусные
тесты и проверки соответствия подтверждают проверенное поведение, но не доказывают
полное совпадение со всеми JVM-инструментами, генераторами и возможностями Freemarker.

Подготовительные работы не добавляют синтаксис языка, диалект, команды или флаги
CLI, переопределения политик либо зависимости. Parse, ParseFile, печать, текст
и стандартная строгость диагностик, а также CLI сохраняют прежнее поведение
на проверяемом корпусе.

## Подтверждение совместимости

- 273 существующих примера соответствия сохраняют ожидаемую валидность.
- Для 55 существующих корпусных примеров сохраняются тесты разбора и печати.
- testdata/compatibility/baseline.json получен из указанного выше неизменённого
  коммита. Он фиксирует ошибки разбора, SHA-256 вывода объединённой модели,
  прежние сообщения, строгость, позиции и порядок диагностик для всех 328 файлов.
- cml/compatibility_test.go сравнивает результат с зафиксированным эталоном.
  До изменения рабочего кода проверено, что тест обнаруживает намеренное
  временное изменение принтера.
- Существующие тесты CLI, генераторов и рефакторингов остаются частью полного набора.

Хеши фиксируют нормализованный вывод принтера, а не побайтовое сохранение исходных
пробелов и комментариев. Точные байты сохраняет Workspace.Source. Это не запуск
дифференциальной проверки рядом с JVM-реализацией. Перед будущим намеренным
изменением примеров необходимо объяснить влияние на совместимость и версию;
обновлять эталон только ради прохождения сломанного теста нельзя.

## Workspace API

```go
workspace, err := cml.LoadWorkspace("architecture.cml")
// Проверить err до обращения к workspace.
// workspace.Entry.Model содержит только локальные объявления входного документа.
// workspace.Entry.Imports сохраняет каждый исходный импорт и его цель.
model, err := workspace.Flatten()
// Проверить err: загруженный граф всё ещё может содержать несколько карт контекстов.
```

Каждый лексически нормализованный абсолютный путь загружается один раз за вызов.
Документы идут в порядке первого обнаружения, связи импортов — в порядке исходника.
Общего кеша процесса нет. При отсутствующих файлах, циклических импортах или
синтаксических ошибках частичный workspace не возвращается. Загрузка ничего
не записывает, но не гарантирует атомарный снимок файловой системы. Альтернативные
пути через symlink, различия регистра и жёсткие ссылки не объединяются.

Flatten сохраняет прежний порядок: импорты раскрываются в порядке объявлений,
после них идут локальные объявления. Повторные и ромбовидные импорты намеренно
повторяют объявления; это может давать диагностики дубликатов имён или ошибку
композиции нескольких карт. Сохраняется ограничение одной ContextMap и порядок
ошибок ParseFile: ошибка композиции вложенного документа возвращается до посещения
следующего соседнего импорта. Изменение этого поведения — отдельное решение
о совместимости, а не неявная оптимизация устранения дубликатов.

Композиция не меняет срезы документов. Результат использует общие с документами
узлы объявлений: вызывающий код владеет объектами и при использовании обоих
представлений должен обращаться с ними как с доступными только для чтения.
Это не глубокая копия, неизменяемое семантическое IR, транзакция редактирования
или гарантия безопасных конкурентных изменений. Для независимого редактирования
нужна отдельная загрузка. ParseFile по-прежнему возвращает объединённое представление.

## API диагностик

Diagnostic и Model.Validate сохраняют исходную структуру и поведение Go API,
включая литералы без имён полей и стандартную JSON-сериализацию.
Model.ValidateDetailed возвращает RuleDiagnostic, включающий исходный Diagnostic,
а также Code и Category. Оба метода выполняют одинаковые проверки с одинаковой
стандартной строгостью и порядком; только подробный результат добавляет метаданные.

Rules() возвращает отсортированный по коду каталог, изменения которого у вызывающего
кода не влияют на проверки; LookupRule возвращает метаданные по устойчивому коду.
Код — машинный идентификатор; переназначать его несвязанной проверке нельзя.
Категории: structure, resolution, semantics, advice. DefaultSeverity сохраняет
прежнюю строгость по умолчанию; категория не определяет, блокирует ли находка
валидацию. Diagnostic.String и CLI сохраняют прежний текст. Ошибки синтаксиса
и загрузки остаются ошибками, а не правилами каталога. Метаданные пока не дают
настраиваемых профилей валидации. Новый JSON-вывод диагностик CLI и гарантированная
схема передачи подробного результата не вводятся.

## Проверка

```sh
go test ./... -count=1
go test -race ./...
go vet ./...
golangci-lint run --timeout=5m
test -z "$(gofmt -l .)"
```

Для существующих интеграционных тестов CLI нужен Graphviz dot. Требуемая версия Go
задаётся модулем. Тесты не читают игнорируемый каталог .reference и не требуют
обращения к upstream или сети. Этапы перехода к самостоятельному DSL описаны
в [принципах развития языка](architecture/evolution.ru.md).
