# Основа для развития диалекта

[English](2026-10-16-dialect-foundation.md) · [Русский](2026-10-16-dialect-foundation.ru.md)

## Назначение

Подготовить go-cml к совместимому расширению языка и в дальнейшем — к самостоятельному
DSL с явной версией. Это изменение не добавляет грамматику, диалект, флаги CLI,
профили валидации, runtime-понятия, механизм политик или универсальную систему
плагинов. Пользователь поручил планирование и реализацию в отдельной ветке.

## Граница совместимости

Context Mapper DSL 6.12 остаётся эталоном существующего CML. Сохраняются Parse,
ParseFile, Model.Validate, Model.String, точки входа генераторов и рефакторингов,
существующие вывод CLI и коды завершения. Метаданные диагностик доступны через
отдельный API ValidateDetailed; прежние текст, строгость, позиции в исходниках
и порядок остаются неизменными. Сохраняются структура экспортируемого Diagnostic,
литералы без имён полей и стандартная JSON-сериализация.

Сохраняется текущая композиция импортов, включая повторение объявлений при
ромбовидных импортах и ограничение одной ContextMap. В подготовительных работах
нельзя незаметно исправлять или переосмысливать эту семантику. Будущие потребители
графа смогут исследовать общие документы без использования этих правил композиции.

## Результаты

1. Workspace API документов сохраняет исходные байты, синтаксические модели
   отдельных файлов, упорядоченные связи импортов и общую идентичность документов.
   ParseFile продолжает возвращать прежнюю объединённую модель. Загрузка отделена
   от композиции.
2. Каталог устойчивых кодов правил валидации, категорий и строгости по умолчанию.
   Каждая сформированная семантическая диагностика идентифицирует своё правило.
   Прежнее поведение валидации сохраняется; переопределения строгости и новый
   разрешающий нарушения профиль не добавляются.
3. Зафиксированный до изменений эталон совместимости по отслеживаемым корпусам CML
   и содержательные тесты загрузки, композиции, идентичности диагностик и изоляции
   каталога.
4. Документация архитектуры и совместимости со ссылками из обоих README: границы
   расширений, известные ограничения и последующий переход к DSL.
5. Проходят существующие тесты, race detector, vet, форматирование и настроенный линтер.

## Проектные решения

cml.Model сохраняется как существующий API модели синтаксиса, а не универсальное
архитектурное IR. Workspace содержит граф импортируемых документов; он не меняет
и не записывает файлы. Идентичность задаётся нормализованными абсолютными
лексическими путями в соответствии с существующим разрешением импортов.
Объединение идентичности symlink, пакетные импорты и гарантия снимка при
конкурентной загрузке не вводятся. Загрузки независимы; общие импорты читаются
один раз в пределах загрузки. API возвращает изменяемые синтаксические объекты,
которыми владеет вызывающий код. Композиция создаёт новые срезы верхнего уровня,
но использует общие узлы объявлений, что явно документируется; это не глубокая
копия и не транзакция редактирования.

Категории правил: structure, resolution, semantics, advice. Это описательные
метаданные, а не разрешение игнорировать ошибки. Существующие проверки могут
смешивать разные задачи; этот этап фиксирует ограничение, сохраняя прежнее
разрешение ссылок. Поиск и перечисление правил возвращают значения, а не
изменяемые внутренние определения каталога.

## Приёмка

Эталон отслеживаемого корпуса должен быть получен из коммита
351c92b1f81081a98381ab76faec7412d987c37e до изменения рабочего кода; нельзя
перегенерировать его ради регрессий. Он фиксирует вывод принтера объединённой
модели и прежние диагностики. Новые тесты подтверждают сохранение документов,
общие импорты, повторяемую композицию без мутаций, циклы, отсутствующие и
некорректные импорты, несколько карт, перезагрузку после правок и согласованность
метаданных правил со значениями по умолчанию. Допустимая грамматика и существующие
ожидания проверок соответствия не меняются.
